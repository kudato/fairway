# Настройка Fairway

Fairway читает настройки плагинов из файлов TOML. В файле параметры
объединяются в таблицы с заголовками вида `[harness]`. Названия таблиц,
допустимые параметры и их значения по умолчанию описывает документация
плагина.

В примерах ниже используется условный плагин с таблицей `[harness]`
и параметрами `listen` и `idle_ttl`.

## Каталог Fairway

Fairway ищет файлы настроек в `~/.fairway`, где `~` — домашний каталог
пользователя. Другой каталог задаёт переменная окружения `FAIRWAY_HOME`:

```sh
export FAIRWAY_HOME=/srv/fairway
```

Если `FAIRWAY_HOME` задан относительным путём, выбор каталога зависит
от того, откуда запущен `fairway`. Например, значение `.fairway` при
запуске из `/work/project` означает `/work/project/.fairway`.
Укажите абсолютный путь, чтобы всегда использовать один каталог.

Если переменная задана, но пуста, Fairway не может определить каталог
и сообщает об ошибке:

```text
error: could not initialize the Fairway filesystem: cannot resolve Fairway home: FAIRWAY_HOME is empty
```

Создавать этот каталог заранее не обязательно. Если файлов настроек нет,
Fairway использует значения по умолчанию, заданные плагинами. Сам каталог
при запуске не создаётся. Пример содержимого:

```text
~/.fairway/
├── config.toml
└── conf.d/
    ├── 10-server.toml
    └── 90-local/
        └── harness.toml
```

`config.toml` и `conf.d` — [файлы конфигурации](#файлы-конфигурации).

## Файлы конфигурации

Fairway читает:

- `config.toml` в каталоге Fairway;
- все файлы `*.toml` из его подкаталога `conf.d`, включая вложенные каталоги.

Любой файл может содержать таблицы любых плагинов, и ни один файл
не обязателен: если таблицы плагина нет ни в одном файле, плагин использует
значения по умолчанию. Сам Fairway в эти файлы ничего не записывает.

Начните с `config.toml`. Каталог `conf.d` позволяет разделить настройки
на несколько файлов. Например, скрипт развёртывания может записывать общие
настройки сервера в один файл, а вы — свои изменения в другой.

Fairway загружает настройки один раз при запуске, перед выполнением
работы плагина. Если изменить файлы настроек во время работы `fairway`,
он продолжит использовать ранее загруженные значения. Чтобы применить
новые настройки, перезапустите `fairway`.

При запросе справки (`--help`), версии (`--version`) или ошибке
в аргументах Fairway завершается до загрузки настроек.

## Порядок файлов

Сначала Fairway читает `config.toml`, затем — файлы из `conf.d`
в лексикографическом порядке их путей. Значения из файлов, прочитанных
позже, переопределяют ранее загруженные.

Пути сравниваются по частям: сначала имена первого уровня внутри `conf.d`,
при совпадении — имена следующего уровня. Сравнение учитывает регистр,
а цифры в имени рассматривает как символы:

- `conf.d/A.toml` применяется раньше `conf.d/a.toml`;
- `conf.d/a/z.toml` применяется раньше `conf.d/b.toml`;
- `conf.d/10-base.toml` применяется раньше `conf.d/2-local.toml`.

Чтобы порядок был очевиден, начинайте имена с номера одинаковой длины:
`10-`, `50-`, `90-`.

## Объединение значений

Fairway объединяет таблицы с одним и тем же именем. Поздний файл меняет
только перечисленные в нём параметры, остальные сохраняются. Вложенные
таблицы объединяются по тому же правилу; строки, числа и массивы
заменяются целиком.

`config.toml`:

```toml
[harness]
listen = "127.0.0.1:8787"
idle_ttl = 300
```

`conf.d/10-server.toml`:

```toml
[harness]
listen = "0.0.0.0:9000"
```

`conf.d/90-local/harness.toml`:

```toml
[harness]
idle_ttl = 60
```

Первый дополнительный файл меняет `listen`, второй — `idle_ttl`.
В результате плагин получит `listen = "0.0.0.0:9000"` и `idle_ttl = 60`.

- Плагин проверяет типы и обязательные параметры после объединения файлов,
  поэтому каждый файл может задавать только часть параметров.
- Массивы, в том числе массивы таблиц `[[...]]`, заменяются целиком:
  элементы из разных файлов не складываются.
- Пустая таблица `[harness]` в позднем файле не сбрасывает настройки.
  Чтобы изменить параметр, задайте новое значение. Чтобы убрать его
  из конфигурации, удалите его из всех файлов, где он указан. Плагин
  подставит значение по умолчанию, только если допускает отсутствие этого
  параметра.

## Какие файлы читаются

- В `conf.d` читаются файлы с расширением `.toml` в нижнем регистре.
  `README.md`, `10-server.toml.bak` и `20-server.TOML` пропускаются.
- Скрытые файлы и каталоги тоже читаются: `conf.d/.local.toml` применяется
  наравне с остальными.
- Символические ссылки на файлы и каталоги разрешаются, `conf.d` тоже может
  быть ссылкой. Битая ссылка внутри `conf.d` — ошибка, как и ссылка
  на родительский каталог, которая зацикливает обход.
- `config.toml` должен быть обычным файлом или ссылкой на обычный файл.

## Значения

- Строки передаются плагину как есть: `~` и переменные окружения
  не раскрываются, относительные пути не привязываются к расположению
  файла. Как плагин понимает относительные пути, описывает его
  документация.
- Fairway проверяет синтаксис всего файла. Если таблица не относится
  ни к одному из доступных плагинов, её параметры пропускаются. Поэтому
  при опечатке в имени, например `[harnes]` вместо `[harness]`, ошибка
  не появится, но настройки из этой таблицы не применятся.

## Ошибки

Перед выполнением работы Fairway проверяет настройки всех плагинов,
включённых в программу. Если настройки хотя бы одного из них загрузить
не удалось, Fairway печатает ошибку и завершается с кодом 1. Это касается
и плагинов, которые вы не собирались использовать в этом запуске.
Значения по умолчанию вместо ошибочных не подставляются.

Загрузка завершается ошибкой, если:

- в любом файле есть синтаксическая ошибка TOML, даже в таблице, которую
  не читает ни один плагин;
- на месте таблицы плагина стоит другое значение, например `harness = 1`;
- параметры не соответствуют правилам плагина: например, вместо числа
  указана строка, отсутствует обязательный параметр или плагин запрещает
  неизвестные параметры;
- файл или каталог не удалось прочитать, ссылка в `conf.d` битая или
  зацикливает обход.

Например, плагин может отклонить неизвестный параметр `port`:

```text
error: could not load Fairway configuration: invalid settings in namespace "harness", assembled from:
  /home/user/.fairway/config.toml
  /home/user/.fairway/conf.d/10-server.toml
  /home/user/.fairway/conf.d/90-local/harness.toml: unknown field `port`, expected `listen` or `idle_ttl`
```

В сообщении `namespace "harness"` означает таблицу `[harness]`.
Перечисленные файлы содержат части её настроек и идут в порядке чтения.
Причина напечатана после последнего файла, но относится к итоговой
таблице: параметр `port` может быть в любом из перечисленных файлов.
