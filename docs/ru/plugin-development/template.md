# fairway-template

Крейт превращает текст шаблона и набор значений в готовую строку.
Данные передаются обычной структурой или картой с `Serialize`.

`Template::compile` подготавливает шаблон, а `Template::render` выполняет
его с переданными значениями. Один подготовленный шаблон можно использовать
много раз. Обе операции синхронные.

Зависимости плагина:

```toml
[dependencies]
fairway-codec.workspace = true
fairway-template.workspace = true
```

## Быстрый старт

```rust
use fairway_codec::serde::Serialize;
use fairway_template::{Error, Template};

#[derive(Serialize)]
#[serde(crate = "fairway_codec::serde")]
struct Report<'a> {
    branch: &'a str,
    files: &'a [&'a str],
}

fn report() -> Result<String, Error> {
    let template = Template::compile(
        "report",
        "Ветка: {{ branch }}\nФайлы: {{ files | join(', ') }}\n",
    )?;

    template.render(&Report {
        branch: "main",
        files: &["one.rs", "two.rs"],
    })
}
```

Результат:

```text
Ветка: main
Файлы: one.rs, two.rs
```

`compile` разбирает исходный текст, проверяет синтаксис и подготавливает
инструкции для исполнения. При вызовах `render` эта работа не повторяется.

## Контекст

Контекст — это именованные значения, доступные шаблону. Поле `branch`
доступно как `{{ branch }}`, а вложенное поле — как `{{ project.name }}`.
`render` принимает как значение, так и ссылку на него. Контекст предыдущих
вызовов не сохраняется.

Имена контекста могут перекрывать встроенные функции MiniJinja.
Например, поле `range` закроет доступ к одноимённой функции.

## Необязательные данные

Состав контекста можно определять во время выполнения. В этом примере
заголовок добавляется только тогда, когда он передан:

```rust
use std::collections::BTreeMap;

use fairway_template::{Error, Template};

fn heading(title: Option<&str>) -> Result<String, Error> {
    let template = Template::compile(
        "heading",
        "{{ title | default('Без названия') }}",
    )?;

    let mut context = BTreeMap::new();
    if let Some(title) = title {
        context.insert("title", title);
    }

    template.render(&context)
}
```

`heading(Some("Отчёт"))` возвращает `"Отчёт"`, а `heading(None)` —
`"Без названия"`. В обоих случаях используется один метод `render`.

Если входных переменных нет, можно передать пустую карту или вызвать
`render(())`.

Шаблоны выполняются по правилам MiniJinja в режиме `Strict`. Если шаблон
выводит `{{ title }}`, а в контексте нет поля `title`, `render` возвращает
ошибку с категорией `ErrorKind::Undefined`.

Фильтр `default` с одним аргументом подставляет запасной текст только
вместо отсутствующего поля:

| Переданные поля | Результат `{{ title \| default('Без названия') }}` |
|---|---|
| Нет поля `title` | `Без названия` |
| `title` равен `"Отчёт"` | `Отчёт` |
| `title` равен `""` | Пустая строка |
| `title` равен `null` | `None` |

Если запасной текст нужен также вместо пустой строки или `null`, используйте
`{{ title | default('Без названия', true) }}`. Этот вариант заменяет
также `false`, `0` и пустые коллекции.

## Откуда берутся данные

Данные готовит вызывающий код. API не позволяет регистрировать функции
потребителя и обработчики получения данных. Встроенные функции и фильтры
языка доступны.

Перед выполнением шаблона контекст целиком сериализуется по правилам
Serde для JSON. Ошибка сериализации возвращается как `ErrorKind::Data`,
даже если проблемное поле не используется в шаблоне.

## Язык шаблонов

Синтаксис шаблонов описан в [руководстве MiniJinja](https://docs.rs/minijinja/latest/minijinja/syntax/index.html).

Загрузки других шаблонов в API нет. Независимо созданные объекты `Template`
не видят друг друга. Синтаксис `include`, `import` и `extends` принимается
как часть MiniJinja, но попытка получить отсутствующий шаблон при рендере
даёт `ErrorKind::Render`. Явный `include ... ignore missing` пропускает
отсутствующий шаблон. Ни одна из этих конструкций не читает файлы.

## Как обрабатывается текст

Автоматическое экранирование по умолчанию выключено независимо от имени
шаблона.

Пробелы и переводы строк сохраняются, включая последний перевод строки
и CRLF, если автор шаблона явно не задаёт их удаление.

## Ошибки

`compile` и `render` возвращают `fairway_template::Error`.
В сообщении указаны имя шаблона и строка, если место ошибки известно:

```text
report:3: cannot render template: undefined value
```

Для обработки в коде доступны `kind()`, `template_name()` и `line()`.
Номер строки начинается с единицы; при ошибке контекста его нет.
Если есть исходная ошибка, она доступна через
`std::error::Error::source()`.

| `ErrorKind` | Что произошло |
|---|---|
| `InvalidName` | Имя пустое или содержит управляющий символ |
| `Syntax` | Ошибка синтаксиса шаблона |
| `Data` | Ошибка сериализации или недопустимый тип контекста |
| `Undefined` | MiniJinja классифицировал ошибку как использование отсутствующего значения |
| `Render` | Другая ошибка вычисления, например недопустимые операнды или неизвестный фильтр |

`Error` реализует `std::error::Error + Send + Sync` и владеет своей
диагностикой. `ErrorKind` объявлен как `#[non_exhaustive]`, поэтому при
сопоставлении всех категорий нужен завершающий вариант `_`.

При ошибке частичная строка не возвращается. Сам шаблон остаётся
пригодным для следующего вызова с другими данными.
