# Файлы

`fairway-fs` позволяет плагину работать с файловой системой пользователя асинхронно.

## Быстрый старт

`read` читает файл целиком. Тип результата определяет представление данных:
`String` — текст UTF-8, `Vec<u8>` — байты, `Json<T>`, `Toml<T>` и `Markdown`
из [fairway-codec](codec.md) — разобранные данные.

`write` принимает текст, байты или значение одного из этих типов кодека.
Запись атомарна: новый файл появляется с готовым содержимым,
а существующий заменяется только после полной записи новых данных.

```rust
use std::{io, path::Path};

use fairway_fs as fs;

async fn uppercase_copy(source: &Path, target: &Path) -> io::Result<()> {
    let text: String = fs::read(source).await?;
    fs::write(target, text.to_uppercase()).await
}
```

## Чтение и запись частями

`reader` открывает файл и возвращает объект `Reader`, который читает байты или строки
по мере обращения к нему. `writer` возвращает объект `Writer`, которому можно
передавать данные частями. Это позволяет обрабатывать большие файлы,
не загружая их целиком в память.

```rust
use std::{io, path::Path};

use fairway_fs as fs;

async fn copy_file(source: &Path, target: &Path) -> io::Result<()> {
    let mut reader = fs::reader(source).await?;
    let mut writer = fs::writer(target).await?;
    let mut buffer = vec![0_u8; 64 * 1024];

    loop {
        let count = reader.read(&mut buffer).await?;
        if count == 0 {
            break;
        }
        writer.write(buffer[..count].to_vec()).await?;
    }

    writer.finish().await
}

async fn print_lines(path: &Path) -> io::Result<()> {
    let mut reader = fs::reader(path).await?;
    while let Some(line) = reader.next_line().await? {
        println!("{line}");
    }
    Ok(())
}
```

`Reader::read` заполняет буфер частично или полностью и возвращает число прочитанных байтов.
`next_line` возвращает строку без завершающего перевода строки или `None` в конце файла.

## Завершение записи

`Writer::write` принимает порцию данных, которая может остаться в буфере.
`flush` дожидается записи всех принятых данных во временный файл.
После `flush` можно продолжать запись.

`finish` выполняет `flush`, затем атомарно переименовывает временный файл
по целевому пути, заменяя существующий файл. Отдельный вызов `flush`
перед `finish` необязателен. До переименования исходный файл сохраняет прежнее
содержимое. Если файла не было, он появляется только после переименования.

```rust
use std::{io, path::Path};

use fairway_fs as fs;

async fn write_result(target: &Path) -> io::Result<()> {
    let mut output = fs::writer(target).await?;

    output.write("Первая часть\n").await?;
    output.flush().await?;

    output.write("Вторая часть\n").await?;
    output.finish().await
}
```

## Редактирование

`edit` читает указанный файл целиком и передаёт его содержимое асинхронной функции.
Функция возвращает новое содержимое, которое `edit` сохраняет атомарно.
С момента чтения до завершения сохранения другие операции `fs` не могут изменить этот файл.

Для редактирования частями используется `editor`. Она возвращает объект `Editor`:
его методы чтения обращаются к исходному файлу, а методы записи — к временному.
`finish` атомарно заменяет исходный файл записанным результатом.

Каждый вызов `edit` или `editor` самостоятельно получает блокировку для указанного пути.
Если другая операция `fs` уже изменяет этот файл, вызов ждёт её завершения
и только затем читает файл.

```rust
use std::{io, path::Path};

use fairway_fs as fs;

async fn uppercase(path: &Path) -> io::Result<()> {
    fs::edit(path, |text: String| async move { Ok(text.to_uppercase()) }).await
}

async fn first_hundred_lines(path: &Path) -> io::Result<()> {
    let mut editor = fs::editor(path).await?;

    for _ in 0..100 {
        let Some(line) = editor.next_line().await? else {
            break;
        };
        editor.write(line).await?;
        editor.write("\n").await?;
    }

    editor.finish().await
}
```

## Форматы данных

Тип результата `read` задаёт формат чтения, тип переданного в `write` значения — формат записи.
Для чтения требуется `Decode`, для записи — `Encode`.
Поддерживаются `Json<T>`, `Toml<T>` и `Markdown` из [fairway-codec](codec.md)
и собственные реализации этих трейтов.

Для JSONL читайте строки через `Reader::next_line` и разбирайте каждую
через `codec::decode`. `Writer::write` с аргументом `Json(value)` записывает
одну JSON-запись с завершающим `\n`. Преобразования выполняются в вычислительном пуле.

```rust
use std::{io, path::Path};

use fairway_codec::{self as codec, Json};
use fairway_fs as fs;

async fn copy_json(source: &Path, target: &Path) -> io::Result<()> {
    let words: Json<Vec<String>> = fs::read(source).await?;
    fs::write(target, words).await
}

async fn copy_jsonl(source: &Path, target: &Path) -> anyhow::Result<()> {
    let mut input = fs::reader(source).await?;
    let mut output = fs::writer(target).await?;
    while let Some(line) = input.next_line().await? {
        let word: Json<String> = codec::decode(line).await?;
        output.write(word).await?;
    }

    output.finish().await?;
    Ok(())
}
```

## Каталоги и метаданные

`ls` позволяет перебрать файлы, подкаталоги и символические ссылки в указанном каталоге.
Для каждой записи доступны имя, путь и тип. Размер и другие свойства файла
или каталога можно получить через `metadata`.

`exists` проверяет, существует ли файл или каталог по указанному пути.
`canonicalize` возвращает абсолютный путь с раскрытыми символическими ссылками.
Путь к служебному каталогу Fairway возвращает `home`.

```rust
use std::io;

use fairway_fs as fs;

async fn list_fairway_files() -> io::Result<()> {
    let directory = fs::home().await?;
    if !fs::exists(&directory).await? {
        println!("Каталог отсутствует: {}", directory.display());
        return Ok(());
    }
    let mut entries: fs::DirEntries = fs::ls(&directory).await?;

    while let Some(entry) = entries.next().await? {
        if entry.file_type().await?.is_file() {
            let path = entry.path();
            let metadata = fs::metadata(&path).await?;
            let resolved = fs::canonicalize(&path).await?;
            println!(
                "{}: {} байт ({})",
                entry.file_name().to_string_lossy(),
                metadata.len(),
                resolved.display()
            );
        }
    }
    Ok(())
}
```

## Временные файлы и каталоги

`temp_file` создаёт временный файл и возвращает объект `TempFile`,
а `temp_dir` создаёт каталог и возвращает `TempDir`.
Метод `path()` возвращает путь, который можно передать в функции `fs`.
`close().await` удаляет файл или каталог и дожидается завершения удаления.

```rust
use std::io;

use fairway_fs as fs;

async fn temporary_data() -> io::Result<()> {
    let file: fs::TempFile = fs::temp_file().await?;
    fs::write(file.path(), "Временные данные").await?;
    let bytes: Vec<u8> = fs::read(file.path()).await?;
    println!("Прочитано {} байт", bytes.len());

    let directory: fs::TempDir = fs::temp_dir().await?;
    let data = directory.path().join("data");
    fs::mkdir(&data).await?;
    fs::write(data.join("input.txt"), "Данные для обработки").await?;

    file.close().await?;
    directory.close().await
}
```

## API

Аргументы пути принимаются как `impl AsRef<Path>`.
Относительные пути разрешаются относительно рабочего каталога в начале операции.
Последующее изменение рабочего каталога не влияет на начатую операцию.
`read`, `reader`, `exists`, `metadata` и `canonicalize` следуют символическим ссылкам.
`Reader`, `Writer`, `Editor`, `DirEntries`, `TempFile` и `TempDir` реализуют `Send`.

### Каталог Fairway

- `home().await -> io::Result<PathBuf>` — возвращает путь к служебному каталогу Fairway.

Путь задаётся переменной окружения `FAIRWAY_HOME`. По умолчанию используется `~/.fairway`.
`fairway-fs` определяет этот путь при запуске Fairway, до загрузки конфигурации,
и сохраняет его на всё время работы.
Если определить путь невозможно, функция возвращает ошибку.

### Чтение

- `read::<T>(path).await -> io::Result<T>` — читает обычный файл целиком и преобразует данные в `T`.
- `reader(path).await -> io::Result<Reader>` — открывает файл для последовательного чтения.

`read` проверяет тип открытого объекта до чтения. Если обнаружен каталог,
именованный канал, устройство или другой специальный файл, возвращается `InvalidInput`.
Ошибки открытия и получения метаданных сохраняют исходный `io::ErrorKind`.
Символическая ссылка на обычный файл допустима.
На Unix открытие именованного канала не ждёт появления отправителя.

Для `read` поддерживаются следующие типы результата:

- `String` — весь файл как текст UTF-8.
- `Vec<u8>` — все байты файла.
- `Json<T>`, `Toml<T>` и `Markdown` из [fairway-codec](codec.md).
- Собственные типы, реализующие `Decode`.

Во всех случаях `read` загружает файл целиком в память.

Объект `Reader`, возвращаемый функцией `reader`, предоставляет методы:

- `read(&mut [u8]).await -> io::Result<usize>` — заполняет буфер частично или полностью
  и возвращает число прочитанных байтов. `0` означает конец файла или пустой буфер.
- `next_line().await -> io::Result<Option<String>>` — возвращает следующую строку
  без завершающего `\n` или `\r\n`. В конце файла возвращает `None`.

`Reader` начинает чтение с начала файла. Оба метода используют общую позицию:
каждый вызов продолжает чтение с того места, где остановился предыдущий.
`next_line` возвращает и последнюю строку без перевода строки.
Для пустой строки результат — `Some(String::new())`.
При отмене `next_line` уже прочитанная часть строки сохраняется для следующего вызова.

`read` и `reader` не ждут завершения записи. Если файл заменён после открытия,
чтение продолжается из прежнего файла. При следующем открытии будет прочитана
версия, доступная по указанному пути в этот момент.

### Запись

- `write(path, contents).await -> io::Result<()>` — атомарно записывает содержимое
  в новый файл или заменяет существующий файл.
- `writer(path).await -> io::Result<Writer>` — подготавливает временный файл для записи частями.

Объект `Writer`, возвращаемый функцией `writer`, предоставляет методы:

- `write(contents).await -> io::Result<()>` — принимает всю переданную часть данных.
  Часть данных может оставаться в буфере до следующей записи, `flush` или `finish`.
- `flush().await -> io::Result<()>` — записывает содержимое буфера во временный файл
  и дожидается завершения записи в ОС.
- `finish(self).await -> io::Result<()>` — выполняет `flush`, затем атомарно
  переименовывает временный файл по целевому пути, заменяя существующий файл.

Размер внутреннего буфера ограничен и не растёт вместе с файлом.
При нехватке места `write` сам сбрасывает буфер, ожидая возможности продолжить запись.
Вызывать `flush` после каждой порции не требуется.

Аргумент `contents: V` требует `V: Encode + Send + 'static` и передаётся по значению.
Для текста и байтов передавайте `String`, `Vec<u8>` или строковый литерал.
Срез локального буфера нужно скопировать в собственный `Vec<u8>`.
`fs::write` преобразует всё содержимое до записи, а `Writer::write` — переданную часть.

Временный файл создаётся в том же каталоге, что и целевой.
До переименования существующий файл сохраняет прежнее содержимое,
а отсутствующий ещё не появляется. После успешного `fs::write` или `finish`
по указанному пути находится файл со всеми записанными данными.
Ошибка до переименования оставляет исходный файл неизменным.
Если атомарное переименование невозможно, операция возвращает ошибку.

Родительский каталог должен существовать. По указанному пути допускается обычный
файл или отсутствие файла. Если последний компонент пути — символическая ссылка,
в том числе битая, каталог или специальный файл, операция возвращает ошибку.
Символические ссылки на родительские каталоги допустимы.

При замене по указанному пути появляется новый объект файла.
Другие жёсткие ссылки и открытые ранее дескрипторы продолжают ссылаться на прежний объект.
Права доступа, владелец, группа, ACL и расширенные атрибуты переносятся с исходного файла.
Если перенос не удался, исходный файл не заменяется.
Резервные копии не создаются.

После успешного `fs::write`, `fs::edit`, `flush` или `finish` данные переданы ОС.
За их дальнейшее сохранение на накопителе отвечает ОС.

После ошибки `Writer::write` или `flush`, а также после отмены начавшегося
`Writer::write`, метод `finish` возвращает ошибку и не заменяет целевой файл.

Отмена ожидания `Writer::flush` или `Editor::flush` не отбрасывает данные.
После неё можно продолжать запись, повторить `flush` или вызвать `finish`.
Уже выполненная часть записи учитывается, оставшиеся данные записываются в исходном порядке.

`Writer` и `Editor` не реализуют `Clone`. При их освобождении без `finish`
исходный файл остаётся прежним, а удаление временного файла запускается в фоне.
После аварийного завершения временный файл может остаться.

Отмена ожидания `fs::write`, `fs::edit` или `finish` не гарантирует остановку
уже начатого сохранения. Блокировка удерживается до завершения фоновой работы.
Замена может произойти после отмены, но только полностью записанным файлом.

### Редактирование

- `edit(path, handler).await -> Result<(), E>` — читает файл целиком, вызывает
  асинхронный обработчик и сохраняет возвращённое значение под одной блокировкой.
- `editor(path).await -> io::Result<Editor>` — открывает исходный файл для чтения
  и временный файл для нового содержимого под одной блокировкой.

После успешного чтения и декодирования `edit` вызывает `handler` один раз.
Обработчик получает содержимое файла и асинхронно возвращает `Result<T, E>`.
`T` — тип исходного и нового содержимого, например `String`.
`E` — тип ошибки обработчика.

Требования к обработчику:

- Тип содержимого `T` реализует `Decode` для чтения и `Encode` для сохранения результата.
- `T: Send + 'static` позволяет передать содержимое в вычислительный пул.
  Значение не должно содержать заимствованных ссылок на локальные данные вызывающего кода.
- Возвращаемая обработчиком future реализует `Send`, чтобы её можно было передавать между потоками.
- Тип ошибки `E` реализует `From<io::Error>`, чтобы `edit` мог возвращать ошибки
  файловых операций через тот же тип. Подходят, например, `io::Error` и `anyhow::Error`.

Для ошибок `Decode` и `Encode` действуют общие [требования к преобразованию данных](#преобразование-данных).
Ошибки декодирования и кодирования преобразуются в `io::Error`.
Ошибка чтения, преобразования или обработчика оставляет файл неизменным.

`edit` и `editor` требуют существующий обычный файл. Отсутствующий файл — `NotFound`.
Проверка и чтение выполняются после получения блокировки.
Правила атомарной записи, обработки ссылок и переноса метаданных те же, что у `write`.

Объект `Editor`, возвращаемый функцией `editor`, предоставляет методы:

- `read(&mut [u8]).await -> io::Result<usize>` — читает байты исходного файла.
- `next_line().await -> io::Result<Option<String>>` — читает строку исходного файла.
- `write(contents).await -> io::Result<()>` — записывает часть нового содержимого.
- `flush().await -> io::Result<()>` — сбрасывает буфер во временный файл.
- `finish(self).await -> io::Result<()>` — атомарно заменяет исходный файл результатом.

Методы чтения `Editor` работают как у `Reader`, методы записи — как у `Writer`,
с тем же требованием `V: Encode + Send + 'static`.
Позиции чтения и записи независимы. `finish` сохраняет только записанное содержимое:
дочитывать исходник необязательно, остаток не копируется, отсутствие записи даёт пустой файл.
Ошибка чтения, записи или `flush`, а также отмена начавшегося `Editor::write`
запрещает сохранение: последующий `finish` возвращает ошибку.

### Координация

Изменения одного пути защищены внутренней межпроцессной блокировкой `FileLock`.
Перед выбором блокировки родительский каталог приводится к абсолютному
каноническому пути с разрешением символических ссылок. Для одного имени файла
в этом каталоге используется одна блокировка, в том числе при обращении через
символическую ссылку на каталог.

`write` и `edit` удерживают её на протяжении операции.
`writer` и `editor` получают блокировку до открытия файлов и передают её
возвращаемому объекту; она удерживается до завершения записи или отказа от результата.

При занятой блокировке `write` и `writer` возвращают `WouldBlock`.
`edit` и `editor` ожидают освобождения асинхронно, без встроенного таймаута.
Ожидание можно отменить; файл до получения блокировки не изменяется.
В одном процессе ожидающие редактирования сохраняют порядок постановки в очередь.
Между процессами порядок не гарантируется. Разные целевые пути обрабатываются независимо.
Отдельные вызовы `read` и `write` не образуют защищённого редактирования.

`fs` создаёт каталог `locks` внутри каталога Fairway и управляет файлами блокировок.
Процессы с одним корнем Fairway используют общие блокировки.
После завершения операции файл блокировки удаляется; свободные файлы,
оставшиеся после аварии, очищаются при следующем запуске. Занятые файлы сохраняются.

Открытие, захват и удаление файлов блокировок согласуются через постоянный
`locks/.coordination.lock`. Он удерживается только на время служебных действий.
При неудачной попытке ожидающий закрывает файл блокировки до освобождения
`.coordination.lock` и открывает его заново при следующей попытке.
Сам `.coordination.lock` не удаляется.

### Каталоги

- `mkdir(path).await -> io::Result<()>` — создаёт каталог с родителями.
  Существующий каталог допустим, файл — ошибка.
- `ls(path).await -> io::Result<DirEntries>` — открывает перебор каталога.

При ошибке `mkdir` уже созданные каталоги остаются.
Перебор каталога включает скрытые записи, без рекурсии, сортировки и снимка.
Ошибка возможна при открытии и чтении записи.

Объект `DirEntries`, возвращаемый функцией `ls`, предоставляет метод:

- `next().await -> io::Result<Option<DirEntry>>` — возвращает очередную запись
  или `None` в конце перебора.

Каждая запись представлена объектом `DirEntry` с методами:

- `path() -> PathBuf` — возвращает путь записи.
- `file_name() -> OsString` — возвращает имя записи.
- `file_type().await -> io::Result<std::fs::FileType>` — возвращает тип самой записи,
  без перехода по символической ссылке.

### Существование и метаданные

- `exists(path).await -> io::Result<bool>` — проверяет наличие пути, ничего не создавая.
- `metadata(path).await -> io::Result<std::fs::Metadata>` — возвращает метаданные файла или каталога.
- `canonicalize(path).await -> io::Result<PathBuf>` — возвращает абсолютный путь
  с раскрытыми символическими ссылками.

`exists` возвращает `false` для отсутствующего пути или битой ссылки.
Невозможность проверки, в том числе из-за недостатка прав, возвращается как ошибка.
Метаданные отражают состояние на момент запроса.

Для `canonicalize` путь должен существовать. Отсутствующий путь или битая ссылка
возвращают `NotFound`; остальные ошибки файловой системы сохраняются.

### Временные ресурсы

- `temp_file().await -> io::Result<TempFile>` — создаёт пустой временный файл.
- `temp_dir().await -> io::Result<TempDir>` — создаёт пустой временный каталог.

Ресурсы создаются с уникальными именами в системном временном каталоге.
`TempFile` и `TempDir` реализуют `AsRef<Path>` и предоставляют методы:

- `path() -> &Path` — путь ресурса. Копия пути не продлевает его жизнь.
- `close(self).await -> io::Result<()>` — удаляет ресурс и ожидает завершения удаления.
  Каталог удаляется со всем содержимым.

До `close` освобождают открытые читатели, писатели и переборы.
Освобождение объекта без `close` запускает очистку без подтверждения.
После аварии ресурс может остаться.

### Преобразование данных

`Decode` и `Encode` определены в [fairway-codec](codec.md#синхронные-трейты).
Для собственных преобразований добавьте `fairway-codec` в зависимости плагина
и импортируйте трейты из `fairway_codec`.

`read` требует `T: Decode + Send + 'static`, читает все байты файла
и передаёт их в `T::decode(&bytes)`.
`write`, `Writer::write` и `Editor::write` принимают `V: Encode + Send + 'static`.
`edit` использует `Decode` при чтении и `Encode` при сохранении результата обработчика.

Методы трейтов синхронные. `fs` выполняет их в общем с `fairway-codec`
вычислительном пуле, ожидая результат асинхронно.
Ограничение числа одновременно выполняемых преобразований общее для `fs` и `codec`.

При использовании через `fs` типы ошибок `Decode` и `Encode` должны реализовывать
`Into<Box<dyn std::error::Error + Send + Sync + 'static>>`.
Это ограничение файловых операций, а не трейтов кодека.

`Reader` читает байты или строки без разбора формата.
Поддерживаемые форматы и собственные преобразования описаны в [fairway-codec](codec.md).

### Ошибки

Файловые операции возвращают `io::Result`. `edit` возвращает тип ошибки обработчика,
который должен реализовывать `From<io::Error>`.

- Ошибки файловой системы сохраняют исходный `io::ErrorKind`.
- Ошибка декодирования, включая некорректный UTF-8, возвращается как `InvalidData`.
- Ошибка кодирования возвращается как `InvalidInput`.

Исходная ошибка преобразования доступна через `io::Error::get_ref`.
Ошибки встроенных форматов описаны в [документации кодека](codec.md#ошибки).
