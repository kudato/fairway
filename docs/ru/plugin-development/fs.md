# fairway-fs

Асинхронные файловые операции для плагинов Fairway.

Плагин читает и записывает файлы целиком и сразу получает содержимое
в виде значения нужного типа: текста, JSON, TOML или собственного формата.
Запись атомарна: другие программы видят либо старое содержимое файла, либо
новое целиком. Изменения через `edit` не теряются, даже если тот же файл
одновременно меняют другие команды Fairway. Кроме того, крейт работает
с каталогами, временными файлами и каталогом Fairway.

Зависимости плагина (`fairway-codec` нужен для форматов вроде `Json`):

```toml
[dependencies]
fairway-fs.workspace = true
fairway-codec.workspace = true
```

## Быстрый старт

```rust
use std::path::Path;

use fairway_fs as fs;

async fn uppercase_copy(source: &Path, target: &Path) -> anyhow::Result<()> {
    let text: String = fs::read(source).await?;
    fs::write(target, text.to_uppercase()).await?;
    Ok(())
}
```

`read`, `write` и `edit` работают с файлом целиком, поэтому содержимое
должно помещаться в памяти. Формат определяется типом значения: `String` —
текст UTF-8, `Vec<u8>` — байты как есть.

`write` забирает значение во владение, поэтому строковый литерал передают
как `"text".to_owned()`, а срез байтов — как `bytes.to_vec()`.

Все функции асинхронные и работают только внутри Tokio runtime. В обработчике
команды он уже есть, а в тестах подойдёт `#[tokio::test]`. Файловый
ввод-вывод выполняется в отдельном потоке блокирующих операций, там же
`fairway-codec` декодирует и кодирует содержимое, поэтому другие задачи
не ждут.

## Форматы

Подойдёт любой тип из [fairway-codec](codec.md): `Json<T>`, `Toml<T>`,
`Markdown` или собственный формат.

```rust
use std::path::Path;

use fairway_codec::Json;
use fairway_fs as fs;
use serde::{Deserialize, Serialize};

#[derive(Deserialize, Serialize)]
struct Settings {
    theme: String,
}

async fn load(path: &Path) -> Result<Settings, fs::Error> {
    let Json(settings): Json<Settings> = fs::read(path).await?;
    Ok(settings)
}

async fn save(path: &Path, settings: Settings) -> Result<(), fs::Error> {
    fs::write(path, Json(settings)).await
}
```

- Если содержимое не удалось разобрать, например файл, который читают
  в `String`, не в UTF-8, `read` вернёт ошибку вида `InvalidData`. Если
  значение не удалось закодировать, `write` вернёт `InvalidInput`.
- `fairway-codec` преобразует значение в отдельном потоке блокирующих
  операций, поэтому значение должно быть `Send + 'static`: владеть своими
  данными, а не заимствовать их. Вместо `Json(&settings)` передайте само
  значение.

## Изменение файла

`edit` читает файл, передаёт разобранное содержимое обработчику и заменяет
файл значением, которое тот вернул. Всё это время путь заблокирован, поэтому
другие операции Fairway не могут изменить файл между чтением и записью.

```rust
use std::path::Path;

use fairway_codec::Json;
use fairway_fs as fs;

async fn add_tag(path: &Path, tag: String) -> anyhow::Result<()> {
    fs::edit(path, |Json(mut tags): Json<Vec<String>>| async move {
        if tags.contains(&tag) {
            anyhow::bail!("tag {tag} already exists");
        }
        tags.push(tag);
        Ok(Json(tags))
    })
    .await
}
```

- Файл должен существовать и быть доступным для записи. Это проверяется
  до вызова обработчика; если файла нет, будет `NotFound`.
- Обработчик вызывается не более одного раза, а если файл не удалось
  прочитать или разобрать, не вызывается вовсе.
- Обработчик выполняется в той же задаче, что и `edit`, поэтому может
  заимствовать локальные переменные и ждать другие асинхронные операции.
  Future, который он возвращает, должен быть `Send`.
- Если обработчик вернул ошибку, файл не меняется, а `edit` возвращает эту
  ошибку без изменений. Если вернул значение, файл перезаписывается, даже
  когда значение осталось прежним.
- Ошибка обработчика может быть любого типа, в который преобразуется
  `fs::Error`: `fs::Error`, `anyhow::Error` или собственный тип ошибки плагина
  с `From<fs::Error>`. Ошибки самого `edit` приходят преобразованными в этот
  тип.
- Внутри обработчика не вызывайте `edit` для того же файла: вложенный вызов
  будет бесконечно ждать блокировку, которую держит внешний. `write` того же
  файла вернёт `WouldBlock`.

Не заменяйте `edit` парой `read` и `write`: между ними файл может изменить
другая команда, и её изменения пропадут.

## Каталоги и метаданные

```rust
use std::path::Path;

use fairway_fs as fs;

async fn print_sizes(directory: &Path) -> anyhow::Result<()> {
    let mut entries = fs::ls(directory).await?;
    while let Some(entry) = entries.next().await? {
        if entry.file_type().await?.is_file() {
            let size = fs::metadata(entry.path()).await?.len();
            println!("{}: {size} bytes", entry.file_name().to_string_lossy());
        }
    }
    Ok(())
}
```

- `mkdir` создаёт каталог вместе с недостающими родительскими. Если каталог
  уже есть, это не ошибка, поэтому `mkdir` можно вызывать перед каждым
  использованием каталога.
- `ls` перебирает записи одного каталога, включая скрытые, но без `.` и `..`.
  Вложенные каталоги он не обходит, а порядок записей задаёт операционная
  система: если порядок важен, отсортируйте их.
- `file_type` описывает саму запись: для символической ссылки это ссылка.
  Тип файла, на который она указывает, вернёт `metadata(entry.path())`.
- `exists` возвращает `false`, только если пути нет, в том числе если
  символическая ссылка битая. Остальные ошибки, например нехватка прав,
  возвращаются как ошибки.
- `metadata` и `canonicalize` проходят по символическим ссылкам.
  `canonicalize` требует, чтобы существовали все компоненты пути.

## Временные файлы и каталоги

```rust
use fairway_fs as fs;

async fn scratch() -> anyhow::Result<()> {
    let directory = fs::temp_dir().await?;
    let input = directory.path().join("input.txt");
    fs::write(&input, "data".to_owned()).await?;
    let text: String = fs::read(&input).await?;
    println!("{text}");
    directory.close().await?;
    Ok(())
}
```

`temp_file` и `temp_dir` создают пустой файл или каталог с уникальным именем
`fairway-…` в системном временном каталоге. На Unix доступ к нему есть только
у владельца.

`TempFile` и `TempDir` хранят путь, а не открытый файл: работайте с ним через
`path()` любыми средствами. Функциям `fs` их можно передавать вместо пути.

`close` удаляет файл или каталог со всем содержимым и сообщает, если удалить
не удалось. Если `close` не вызвать, объект удаляется при уничтожении:
удаление запускается без ожидания, а его ошибки игнорируются.

## Каталог Fairway

`home()` возвращает абсолютный путь к каталогу Fairway, где находятся
конфигурация и служебные файлы. Fairway определяет этот путь при запуске:
из переменной `FAIRWAY_HOME` или как `~/.fairway`, если переменная не задана.

Если `FAIRWAY_HOME` задан относительным путём, выбор каталога зависит
от того, откуда запущен Fairway. Например, значение `.fairway` при запуске
из `/work/project` означает `/work/project/.fairway`. Определённый при запуске
путь сохраняется до завершения процесса.

`home()` не создаёт каталог.

Если каталог Fairway определить нельзя, например `FAIRWAY_HOME` пуст,
Fairway сообщает об этом при запуске и не вызывает обработчик плагина.

## Ошибки

Функции `fs` возвращают `fs::Error`. В обработчике команды её передают дальше
через `?`, как любую другую ошибку.

Сообщение `fs::Error` называет шаг, который не удался, и путь, если он известен.
Причина указана в самом сообщении или в исходной ошибке, доступной через
`source()`. Fairway выводит всю цепочку ошибок:

```text
error: cannot open /home/user/.fairway/example/state.json: No such file or directory (os error 2)
```

Если выводите ошибку сами, используйте формат `{:#}` у `anyhow::Error`: он
тоже печатает всю цепочку. Путь в сообщении абсолютный, если его удалось
определить; иначе указан путь, переданный функции.

Чтобы отреагировать на определённую ошибку, проверьте `kind()`:

```rust
use std::{io, path::Path};

use fairway_codec::Json;
use fairway_fs as fs;
use serde::Deserialize;

#[derive(Default, Deserialize)]
struct State {
    runs: u32,
}

async fn load_state(path: &Path) -> Result<State, fs::Error> {
    match fs::read::<Json<State>>(path).await {
        Ok(Json(state)) => Ok(state),
        Err(error) if error.kind() == io::ErrorKind::NotFound => Ok(State::default()),
        Err(error) => Err(error),
    }
}
```

Чаще всего встречаются такие виды ошибок:

- `NotFound` — файла или его каталога нет, или путь пустой;
- `PermissionDenied` — нет прав на файл или каталог;
- `WouldBlock` — `write`: файл сейчас изменяет другая операция Fairway;
- `InvalidData` — содержимое не удалось разобрать;
- `InvalidInput` — значение не удалось закодировать, или по пути не обычный
  файл: каталог, специальный файл или, при записи, символическая ссылка.

Остальные виды берутся из ошибки операционной системы. Какие виды возвращает
каждая функция, указано в [документации API](#документация-api).

`operation()` сообщает шаг, на котором произошла ошибка, например
`Operation::Decode`, а `path()` — путь. Ошибку формата с номером строки
и столбца можно получить через `source()` и
`downcast_ref::<fairway_codec::Error>()`. Если `fs::Error` уже превратилась
в `anyhow::Error`, её можно получить обратно через
`downcast_ref::<fs::Error>()`.

## Что важно знать

### Как сохраняется файл

`write` и `edit` не меняют файл на месте. Новое содержимое записывается
во временный файл `.<имя файла>.lock` в том же каталоге, и он одной операцией
занимает место прежнего. Поэтому `read` и другие программы видят либо старое
содержимое целиком, либо новое. При ошибке прежний файл остаётся нетронутым,
а Fairway пытается удалить свой временный файл.

- `write` создаёт файл, если его нет, но родительский каталог должен
  существовать: создайте его через `mkdir`.
- Новый файл получает такие же права, как любой вновь созданный; на Unix —
  с учётом umask.
- Чтобы заменить существующий файл, нужны права на запись и в файл,
  и в каталог. Файл, в который процессу писать нельзя, не заменяется, даже
  если каталог это позволяет.
- При замене файл сохраняет права, владельца, группу, расширенные атрибуты
  и другие метаданные платформы, например ACL, а на Windows — альтернативные
  потоки данных и атрибуты вроде «скрытый». Если перенести их не удалось,
  например потому что файл принадлежит другому пользователю, файл
  не заменяется. Время изменения обновляется.
- По пути должен быть обычный файл или ничего. Символическая ссылка в конце
  пути не подходит: замена подменила бы саму ссылку, а не файл, на который
  она указывает. Чтобы записать такой файл, передайте путь из `canonicalize`.
  Ссылки в родительских каталогах разрешаются автоматически.
- Файл заменяется другим файлом, поэтому открытые ранее дескрипторы
  и жёсткие ссылки на прежний файл продолжают видеть старое содержимое.
- Fairway не ждёт, пока данные физически запишутся на диск (`fsync`). Замена
  атомарна, но после сбоя питания или операционной системы новое содержимое
  может пропасть. Если процесс завершится посреди замены, рядом с файлом может
  остаться `.<имя файла>.lock`. Он блокирует последующие изменения. Убедившись,
  что ни одна операция его не использует, удалите его вручную.

### Одновременный доступ

`write` и `edit` блокируют путь на всё время операции. Поэтому две операции
Fairway не заменяют один файл одновременно, а изменения через `edit`
применяются по очереди и не теряются.

- `read` не использует блокировку и не ждёт записи: благодаря атомарной
  замене он всегда видит одну версию файла целиком.
- `write` не ждёт: если очередь или имя файла блокировки заняты, он возвращает
  `WouldBlock`.
- `edit` ждёт без ограничения по времени. Внутри процесса очередь определяется
  полным путём после `canonicalize`, нормализации Unicode и case folding.
  Ожидающие вызовы одной очереди выполняются по порядку; разные очереди могут
  работать параллельно.
- Между процессами общего порядка ожидания нет. Если разные очереди обращаются
  к одному файлу, от одновременного изменения защищает файл блокировки.
- Для `report.txt` блокировка — `.report.txt.lock` рядом с ним. Fairway создаёт
  её до чтения и использует для нового содержимого. Процессы согласуют запись
  независимо от выбранного [каталога Fairway](#каталог-fairway). Другие программы
  могут изменить целевой файл в любой момент.
- Имя `.<имя файла>.lock` зарезервировано для Fairway. Существующий файл под
  этим именем не перезаписывается. Префикс и суффикс должны помещаться в
  ограничение ФС на длину имени. Оставшиеся после сбоя блокировки при запуске
  не удаляются.
- После успешного возврата `write` или `edit` блокировка снята. При ошибке
  Fairway пытается удалить свой файл блокировки перед возвратом. При отмене
  или панике очистка выполняется в фоне, удерживая очередь до завершения
  оставшейся работы.

### Паники

Паника в `Decode::decode` или `Encode::encode` не превращается в ошибку: она
продолжается в задаче, которая ждёт `read`, `write` или `edit`, как если бы
преобразование выполнялось прямо в ней. Обработчик `edit` и так выполняется
в этой задаче. После паники во время `write` или `edit` файл остаётся
прежним.

### Пути

- Путь — любой `impl AsRef<Path>`: `&Path`, `PathBuf`, `&str`, `String`,
  а также `TempFile` и `TempDir`.
- Относительный путь отсчитывается от текущего каталога процесса в момент
  начала операции.
- Пустой путь даёт `NotFound`.
