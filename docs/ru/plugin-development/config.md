# Настройки

`fairway-config` предоставляет плагину типизированные настройки из `config.toml`
и дополнительных TOML-файлов в каталоге `conf.d`.

## Быстрый старт

`Namespace<T>` связывает имя таблицы с типом настроек.
`namespace!(EXAMPLE: Settings, "example")` объявляет пространство:
`EXAMPLE` — имя объекта в Rust-коде, `Settings` — тип настроек,
`"example"` — имя таблицы в конфигурации.

Fairway загружает настройки при старте, до вызова обработчика команды.
`get()` синхронно возвращает подготовленное значение.

```rust
// src/settings.rs

use serde::Deserialize;

#[derive(Default, Deserialize)]
#[serde(default, deny_unknown_fields)]
pub(crate) struct Settings {
    pub(crate) enabled: bool,
}

fairway_config::namespace!(EXAMPLE: Settings, "example");

pub(crate) fn is_enabled() -> bool {
    EXAMPLE.get().enabled
}
```

`config.toml`:

```toml
[example]
enabled = true
```

## Значения по умолчанию

Если таблица отсутствует во всех файлах, используется `Settings::default()`.
Для присутствующей таблицы `#[serde(default)]` на структуре заполняет
пропущенные поля значениями из `Default`.
`#[serde(deny_unknown_fields)]` отклоняет неизвестные поля.

```rust
// src/settings.rs

use std::net::{Ipv4Addr, SocketAddr};

use serde::Deserialize;

#[derive(Deserialize)]
#[serde(default, deny_unknown_fields)]
pub(crate) struct Settings {
    pub(crate) listen: SocketAddr,
    pub(crate) idle_ttl: u64,
}

impl Default for Settings {
    fn default() -> Self {
        Self {
            listen: SocketAddr::from((Ipv4Addr::LOCALHOST, 8787)),
            idle_ttl: 300,
        }
    }
}

fairway_config::namespace!(HARNESS: Settings, "harness");

pub(crate) fn print_settings() {
    let settings = HARNESS.get();
    println!("{} ({} s)", settings.listen, settings.idle_ttl);
}
```

`config.toml`:

```toml
[harness]
listen = "127.0.0.1:9000"
```

`HARNESS.get()` возвращает `listen = 127.0.0.1:9000` и `idle_ttl = 300`.

## Дополнительные файлы

`conf.d` находится рядом с `config.toml`. TOML-файлы читаются также
из вложенных каталогов. Каждый файл содержит обычные таблицы конфигурации;
имена файлов и каталогов не задают пространство настроек.

```text
~/.fairway/
├── config.toml
└── conf.d/
    ├── 10-server.toml
    └── 90-local/
        └── harness.toml
```

Сначала применяется `config.toml`, затем файлы из `conf.d` в порядке
их относительных путей. Таблицы объединяются по ключам;
более позднее значение заменяет более раннее.

`config.toml`:

```toml
[harness]
listen = "127.0.0.1:8787"
idle_ttl = 300
```

`conf.d/10-server.toml`:

```toml
[harness]
idle_ttl = 60
```

`conf.d/90-local/harness.toml`:

```toml
[harness]
listen = "127.0.0.1:9000"
```

Для объявленного выше `HARNESS` итоговые значения —
`listen = 127.0.0.1:9000` и `idle_ttl = 60`.
Плагин получает их тем же вызовом `HARNESS.get()`.

## Независимые пространства настроек

Несколько объявлений `namespace!` с одинаковым типом и разными именами
таблиц создают независимые настройки.

```rust
// src/settings.rs

use serde::Deserialize;

#[derive(Default, Deserialize)]
#[serde(default, deny_unknown_fields)]
pub(crate) struct Settings {
    pub(crate) enabled: bool,
}

fairway_config::namespace!(PRIMARY: Settings, "primary");
fairway_config::namespace!(SECONDARY: Settings, "secondary");

pub(crate) fn print_settings() {
    println!("primary: {}", PRIMARY.get().enabled);
    println!("secondary: {}", SECONDARY.get().enabled);
}
```

`config.toml`:

```toml
[primary]
enabled = true

[secondary]
enabled = false
```

## API

### Регистрация

- `namespace!(NAME: T, "table")` — объявляет
  `pub(crate) static NAME: Namespace<T>` и регистрирует пространство настроек.

`T` реализует `Default + serde::de::DeserializeOwned + Send + Sync + 'static`.
`Clone` и `Serialize` не требуются. Видимость типа и полей определяется тем,
каким модулям плагина нужен доступ к настройкам; для загрузки Fairway
открывать поля не требуется.

Имя пространства — непустая строка без пробелов и управляющих символов.
Оно обозначает один ключ верхнего уровня TOML, с учётом регистра.
Имя с точкой записывается в TOML в кавычках: `"foo.bar"` соответствует
таблице `["foo.bar"]`. Таблица `[foo.bar]` относится к пространству `"foo"`.

Имена уникальны среди пространств конфигурации подключённых крейтов.
Один крейт может объявлять несколько пространств, в том числе одного типа.
Пространства CLI и конфигурации регистрируются независимо;
их имена не обязаны совпадать с именами крейтов или друг с другом.

Повторы имён проверяет общий тест приложения: `cargo test -p fairway`.
Проверка охватывает плагины и Cargo features, подключённые в этой сборке;
`cargo build` сам её не запускает. При конфликте диагностика указывает
оба места объявления. Проверка не читает пользовательскую конфигурацию.

### Доступ

Объект `Namespace<T>`, объявленный через `namespace!`, предоставляет метод:

- `get(&'static self) -> &'static T` — возвращает подготовленные настройки.

`get()` доступен из обработчика команды и запущенных им задач.
Метод не выполняет ввод-вывод, не десериализует данные и не копирует `T`.
Повторные вызовы для одного пространства возвращают одну и ту же ссылку
до завершения процесса. Разные пространства одного типа содержат отдельные значения.

Плагин не вызывает загрузку самостоятельно. Вызов `get()` до успешного
завершения загрузки приводит к панике. Это относится также к вызовам
из `Default` и `Deserialize` других настроек: порядок подготовки пространств
не задаёт зависимости между ними.

### Источники

Пути определяются относительно каталога Fairway, возвращаемого
[`fairway_fs::home`](fs.md#каталог-fairway):

- `config.toml` — основной файл.
- `conf.d` — каталог дополнительных файлов с рекурсивным обходом подкаталогов.

По умолчанию корень — `~/.fairway`. Переменная `FAIRWAY_HOME` меняет его
по правилам `fs::home`; конфигурация использует тот же зафиксированный путь.
Загрузка не создаёт каталоги и файлы и не записывает значения по умолчанию.

Отсутствующие `config.toml` и `conf.d` допустимы независимо друг от друга.
`NotFound` при открытии основного файла или корня `conf.d` означает
отсутствие соответствующего источника. Если оба отсутствуют,
все пространства получают значения по умолчанию.

В `conf.d` выбираются файлы с расширением `.toml`, с учётом регистра.
Скрытые файлы и каталоги участвуют в обходе на общих основаниях.
Файлы с другими расширениями пропускаются. Пустой TOML-файл допустим.

Символические ссылки на файлы и каталоги разрешаются при чтении и обходе.
Цикл ссылок на каталоги — ошибка загрузки. Порядок применения определяется
путём внутри `conf.d`, а не расположением цели ссылки.
Если один файл доступен по нескольким выбранным путям, каждый путь участвует
в загрузке отдельно.

Основной файл и выбранные дополнительные файлы должны быть обычными файлами.
`conf.d` должен быть каталогом. Ошибка обхода или чтения, в том числе
исчезновение уже найденного файла или подкаталога, прерывает загрузку.

### Порядок применения

1. Прочитать `config.toml`, если он существует.
2. Собрать файлы из `conf.d` и его подкаталогов.
3. Применить дополнительные файлы в лексикографическом порядке
   компонентов пути относительно `conf.d`, с учётом регистра.
4. Десериализовать итоговую таблицу каждого зарегистрированного пространства в `T`.

Порядок не зависит от порядка записей, возвращённого файловой системой.
Числа в именах сравниваются как текст: `10.toml` предшествует `2.toml`.
Сначала сравниваются родительские компоненты пути, затем имена файлов внутри них;
номер в имени файла не задаёт общий приоритет вне его каталога.

### Объединение

Каждый файл разбирается как самостоятельный TOML-документ.
Зарегистрированное пространство должно быть таблицей в каждом файле,
где оно присутствует. Одна таблица может дополняться несколькими файлами.

Для совпадающего ключа действуют правила:

- Две таблицы объединяются рекурсивно по ключам, включая вложенные таблицы.
- Во всех остальных случаях позднее значение полностью заменяет раннее.
  Это относится и к замене значения другим TOML-типом.
- Массивы, в том числе массивы таблиц, заменяются целиком.
  Элементы не дописываются и не объединяются по индексу или имени.
- Ключи, отсутствующие в позднем файле, сохраняют прежние значения.
  Пустая таблица не очищает прежнюю таблицу; пустой массив заменяет прежний массив.

Проверка типа `T`, обязательных полей и правил десериализации выполняется
после объединения. Отдельный файл может содержать только часть настроек.
Повтор ключа внутри одного файла подчиняется правилам TOML и является ошибкой;
совпадение ключей между файлами обрабатывается по правилам объединения.

Незарегистрированные ключи верхнего уровня игнорируются. Это позволяет
использовать одни файлы с разными наборами плагинов. Опечатка в имени
пространства также будет пропущена. Синтаксис и UTF-8 проверяются во всех
выбранных файлах, включая содержимое незарегистрированных пространств.

Строки передаются в настройки без подстановки переменных окружения или `~`.
Относительные пути в полях автоматически не привязываются к каталогу файла.
Их смысл определяет плагин.

### Значения по умолчанию и проверка

- Пространство отсутствует во всех файлах — вызывается `T::default()`.
- Таблица присутствует, в том числе пустая, — вызывается десериализация в `T`.
- При `#[serde(default)]` на структуре пропущенные поля заполняются из `T::default()`.
  Атрибуты отдельных полей могут задавать собственные значения по умолчанию.
- Без правила заполнения обязательное пропущенное поле вызывает ошибку.
  Само требование `T: Default` не делает поля необязательными при десериализации.

Значения по умолчанию применяются после объединения файлов.
Вложенные типы задают собственные правила пропущенных и неизвестных полей.
Атрибуты следуют [правилам Serde](https://serde.rs/container-attrs.html).

Проверки диапазонов и связей между полями выполняются при десериализации,
например через `#[serde(try_from = "RawSettings")]`.
При отсутствии таблицы десериализация не вызывается:
`Default` должен возвращать корректные настройки самостоятельно.

### Выполнение

Fairway загружает конфигурацию один раз при старте, после разбора CLI
и до вызова обработчика команды. Справка, версия и ошибки аргументов CLI
не требуют загрузки настроек. Функции разбора аргументов и выбора `workers`
выполняются до загрузки и не могут обращаться к `get()`.

Файловые операции выполняются через `fairway-fs` асинхронно.
Разбор TOML, объединение и подготовка значений выполняются в общем
вычислительном пуле [fairway-compute](compute.md), освобождая рабочие потоки Tokio.
Последующий доступ через `get()` синхронный, поскольку значение уже находится в памяти.

Загружаются все зарегистрированные пространства. Ошибка любого из них
останавливает запуск команды. Значения становятся доступны только после
успешной подготовки всей конфигурации; частично подготовленные настройки
не используются. В памяти должны помещаться объединённая конфигурация
и подготавливаемые значения.

Изменения файлов после загрузки применяются при следующем запуске процесса.
Чтение нескольких файлов не образует общий снимок файловой системы.
Для отдельного файла действуют [правила чтения `fs`](fs.md#чтение).

### Ошибки

- Неподходящий тип `T` или недопустимое имя пространства — ошибка компиляции объявления.
- Повтор имени пространства — ошибка общего теста регистрации приложения.
- Ошибка определения каталога Fairway, обхода `conf.d` или чтения файла — ошибка загрузки.
  Отсутствие основных источников обрабатывается по [правилам источников](#источники).
- Некорректный UTF-8 или TOML в любом выбранном файле — ошибка загрузки,
  даже если его значения перекрываются последующими файлами.
- Значение зарегистрированного пространства не является таблицей — ошибка загрузки.
- Несовместимый тип значения, пропущенное обязательное поле или ошибка проверки
  при десериализации итоговых настроек — ошибка загрузки пространства.
- Неизвестное поле при `#[serde(deny_unknown_fields)]` — ошибка загрузки пространства.
- Вызов `get()` до успешной загрузки — паника из-за нарушения порядка инициализации.

Диагностика ошибки обхода или чтения содержит путь и причину.
Ошибка TOML содержит путь к файлу и позицию, если она известна.
Ошибка итоговых настроек содержит имя пространства, причину и список файлов,
из которых составлена его таблица; путь к полю добавляется, если он известен.
Исходная ошибка сохраняется в цепочке `std::error::Error::source()`.

При ошибке загрузки Fairway выводит диагностику в stderr и завершается
с кодом `1`, не вызывая обработчик команды. Ошибка не заменяется значениями по умолчанию.
